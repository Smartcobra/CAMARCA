CAMARCA — Complete Technical Guide

Production-oriented root cause analysis (RCA) for microservice incidents using logs, traces, and metrics. This document maps the repository: architecture, each major module, configuration, data flow, and copy-paste examples.

1. Overview

CAMARCA implements a hybrid RCA stack: classical multi-modal signal processing (graph + statistics) plus optional LLM agents for narrative reasoning and validation. The default ranking path does not require an API key; OpenAI is optional for richer explanations.

Typical inputs: a fault time window (UTC ISO timestamps in a prompt or explicit pd.Timestamp range).

Typical outputs: a ranked list of candidate services, modality confidence scores, an optional competition-style JSON (component, reason, reasoning trace), and debug tables on the result object.

3. Pipeline: what runs in order

The function run_hybrid_window(start, end) in camarca/pipeline.py orchestrates the run. The following is the logical sequence.

  1. Load fault-window data — _load_window_data: logs, traces, metrics filtered to [start, end) in nanoseconds. Metrics may expand with a short “halo” (60s / 300s / 900s) if the strict slice is empty (sampling can miss very short windows).
  2. Per-modality products — _modal_products: log templates, trace enrichment (parent service), metric prep + IsolationForest anomaly flags.
  3. Baseline windows — _load_baseline_window_data: same duration before and after the fault, separated by a 600s gap, for normal-reference comparison in fusion.
  4. Dynamic graph — build_dynamic_service_dependency_graph (NetworkX DiGraph) from traces, templates, and scored metrics; edges carry causality-style scores.
  5. Residual confidence fusion — residual_confidence_fusion: per-service score combining trace, metric, log, and graph terms plus baseline delta (see section 8).
  6. Modality confidences — modality_confidences: global trust weights for trace / metric / log in the window.
  7. Result object — HybridRCAResult with rankings, graph, dataframes, and baselines for downstream formatting or LLM calls.

4. Module reference

4.1 camarca/ingest.py

Role: Load ground truth, logs, traces, and metrics; normalize all time columns to UTC and integer nanoseconds (timestamp_ns); apply filter_time_window; time-bucket rows for alignment (TIME_BUCKET_SECONDS from config, default 30s).

Performance: Prefers Parquet over CSV when PREFER_PARQUET is true; optional column pruning via INGEST_COLUMNS_* in camarca/config.py.

4.2 camarca/pipeline.py

Role: Orchestration and output formatting.

SymbolPurpose
HybridRCAResultDataclass: start, end, rows (counts), dynamic_graph, fused_ranking, modality_confidence, optional llm_trace, GT fields, and dataframe attachments.
run_hybrid_windowMain hybrid run from explicit timestamps.
run_hybrid_from_promptParses two ISO UTC times from text, then calls run_hybrid_window.
compare_with_ground_truthJoins in-window events from data/graound_truth/groundtruth-2022-05-09.csv; sets gt_top1_match when top prediction matches GT service prefix.
format_competition_outputBuilds competition JSON: uuid, component, reason, 3-step reasoning trace (metrics, trace, log evidence snippets).
iterative_reasoningFour LLM steps (hypothesis, cross-modal validate, refine, supervisor) when used with RCAAgentPack.
default_agent_payloadsCompact JSON strings for LLM agents from a HybridRCAResult.

4.3 camarca/analysis.py

Role: Feature construction, service labeling, call graph, anomaly detection, and hybrid fusion. Highlights:

  • add_service_column / normalize_metric_service_label — canonical service names from pods, cmdb_id, etc.
  • enrich_trace_with_parent_service — resolves caller service per span for dependency edges.
  • apply_log_templates — lightweight regex-based log templating; aggregates by template and service.
  • prepare_metrics_for_anomaly + detect_anomalies — IsolationForest on numeric metric features; per-row is_anomaly flags.
  • build_dynamic_service_dependency_graph — directed graph on services; edge attributes include a blended graph_causality_score (latency, errors, call frequency, etc.; see config.py weights).
  • residual_confidence_fusion — per-service fusion score; incorporates fan-in dampening, leaf vs hub heuristics, broadcaster penalty for high out-degree “gateway” nodes, and baseline delta from pre/post windows.
  • modality_confidences — calibrates global trace / metric / log confidences (log capped so it does not dominate).

Mathematical interpretation (practical)

Internally, most service-level terms are normalized to [0, 1] so modalities can be fused without one raw scale (for example request counts) dominating another (for example latency means). A common normalization shape is: 

x_norm(s) = (x(s) - min_s x(s)) / (max_s x(s) - min_s x(s) + ε)

For metrics, IsolationForest assigns each row a binary anomaly decision: 

is_anomaly_i = 1 if IF(x_i) = -1 else 0

Service anomaly signal is then aggregated per service (count of anomalous rows) and normalized before fusion. The final service score is a weighted combination of modality and graph evidence: 

score(s) =
  w_t · c_t · trace_signal(s)
+ w_m · c_m · metric_signal(s)
+ w_l · c_l · log_signal(s) · hub_scale(s)
+ w_g · graph_signal(s)
+ λ · baseline_delta(s)

score'(s) = score(s) / (1 + broadcaster_penalty · max(0, out_degree(s) - gateway_floor))

where c_t, c_m, c_l are global modality confidences from modality_confidences, and baseline_delta(s) measures deviation of the fault window from pre/post reference windows. Intuitively: high local anomaly + strong incoming graph pressure + clear baseline shift pushes a service upward in rank.

4.4 camarca/cache_store.py

SHA1-keyed Parquet files under a cache directory. Used by the pipeline to avoid re-slicing huge day-level files for repeated same-window queries.

4.5 camarca/prompt_pack.py and camarca/rca_openai.py

RCAAgentPack holds structured prompts (log, trace, metric, graph, supervisor) with JSON output contracts and shared guardrails (“no invented services”). run_openai_rca runs the pack; rca_openai.py is a CLI that hydrates agent inputs from default_agent_payloads(run_hybrid_from_prompt(...)) and writes JSON (default outputs/rca_openai.json).

camarca/settings.py loads .env for OpenAI model and API configuration.

4.6 camarca/cli.py, camarca/__main__.py, main.py

uv run camarca executes the CLI: parses natural-language window, runs hybrid + optional GT compare, prints competition JSON. Flags include --with-llm, --output-format debug|competition, --component-granularity predicted|gt-aligned, and force overrides for component or reason text.

4.7 camarca/web_api.py and streamlit_app.py

FastAPI exposes GET /health, GET /api/rca?prompt=..., and GET /api/stream?prompt=... (Server-Sent Events: status steps then final result). CORS is open for local UI use.

Streamlit connects to the API base URL, consumes the SSE stream for progress, and displays the JSON payload. Start API first, then streamlit run streamlit_app.py.

4.8 advanced_evaluation.py

Offline evaluation: loads cases from ground truth, runs run_hybrid_window per case, supports fusion-weight tuning, failure-type boosts, optional LLM reranker, confusion matrices, and charts under outputs/. Suited for benchmarking, not required for a single interactive RCA run.

5. Data and directory layout

Expected at runtime (paths referenced in code):

  • data/logs/, data/traces/, data/metrics/ — day-stamped inputs (e.g. 2022-05-09).
  • data/partitioned/<modality>/dt=YYYY-MM-DD/hour=HH/ — optional fast path for window loads.
  • data/graound_truth/groundtruth-2022-05-09.csv — used by compare_with_ground_truth and evaluation (note the folder spelling in the repo).
  • outputs/cache/windows/ — automatic Parquet window cache.
  • outputs/ — evaluation figures, OpenAI JSON, etc.

7. Runnable examples

7.1 CLI (hybrid RCA, competition JSON)

uv sync
cp .env.example .env   # only if you use OpenAI features

uv run camarca --prompt "A fault occurred from 2022-05-09T06:40:17Z to 2022-05-09T06:50:17Z. Please identify the root cause."

# Debug: print window, row counts, top-5 fusion, GT overlap
uv run camarca --prompt "..." --output-format debug

# Optional LLM pass (requires OPENAI_API_KEY)
uv run camarca --prompt "..." --with-llm --model gpt-4o-mini

7.2 Python API (programmatic window)

from camarca.pipeline import run_hybrid_window
import pandas as pd

start = pd.Timestamp("2022-05-09T06:40:17Z")
end = pd.Timestamp("2022-05-09T06:50:17Z")
res = run_hybrid_window(start, end)

print("rows:", res.rows)                          # {logs, traces, metrics} counts
print("top5:", res.fused_ranking[:5])            # (service, score) tuples
print("modality_confidence:", res.modality_confidence)

Same logical run as a natural-language prompt, but with explicit control over the time range in code.

8. Fusion math (concise)

For each service s, the fusion in residual_confidence_fusion combines normalized per-service signals (trace, metric anomalies, log mass) with global modality confidences and a graph term derived from edge causality scores (with fan-in and leaf heuristics). A baseline-delta term compares fault-window behavior to pre/post reference windows. The implementation also applies a broadcaster penalty when out-degree is high, down-ranking “gateway” style nodes.

Generic shape (see source for exact terms and normalizations):

score(s) ≈
  w_trace  · trace_conf  · trace_signal(s)
+ w_metric · metric_conf · metric_signal(s)
+ w_log    · log_conf    · log_signal(s)   · hub_scale(s)
+ w_graph  · graph_signal(s)
+ λ · baseline_delta(s)

# then optional gateway/broadcaster adjustment from out-degree

Default w_* are set by HYBRID_W_* in config.py. The returned list is sorted by score descending.
